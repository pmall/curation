# Tools

The `curation-*` commands set up and assemble a curation: they fetch and convert full texts, read NCBI sequences and build a batch's publications file, and never touch the database. The Drakkar database is read and written only through its own commands, `database-*` (its `tools.md`).

## Full texts

A full text is fetched and converted by these tools, then read from the files they write.

- `uv run curation-fetch <dir> <pmid>`: downloads the full text as published, in three steps. Each step is a list of routes, each route answering yes or no by one test.

  1. **Access**: the article is free when it has a PMCID, when OpenAlex or Unpaywall list a free copy, or when the publisher's page (at the DOI) declares free access (`"isAccessibleForFree": true`, `<meta name="access" content="Yes">`, `citation_fulltext_world_readable`, or a link to the article's Creative Commons license, PLOS's only declaration); a declared paywall wins. Closed otherwise. A preprint is never a copy of the article: its copies, its DOI and a PMC copy of it (known by its own DOI) are never fetched.
  2. **The article**, one file, from the first route that gives it: the PMC open access files, Europe PMC `fullTextXML`, NCBI `efetch` (each when its XML has a body); the PMC article page, which serves the PMC copies outside the open access files (when it has the body sections; one page per publication, as NCBI forbids bulk downloads); the publisher's HTML page (when it declares free access; a page that declares a paywall is never the article); then, last, the publisher's PDF (`citation_pdf_url`) and the other free copies' PDFs (when the file is a PDF).
  3. **The supplementary files**, as the article lists them: its XML, the supplementary sections of the PMC page, or else the supplementary links of the publisher's page. Each is looked for on every route that serves one, whatever route gave the article: the PMC open access files, the link the article gives (never the PMC website's, which is behind a challenge), the publisher's page, then Europe PMC's supplementary files service. Archives are unpacked. A video, the Reporting Summary and the peer review file (both by their caption) are skipped.

  Unpaywall is asked only with an address, `UNPAYWALL_EMAIL` in the project's `.env`. It writes the article, `<pmid>.xml`, `<pmid>.html` or `<pmid>.pdf`, the supplementary files in `<pmid>.supp/`, and the article's figures, the other images of the PMC open access files, in `<pmid>.fig/`. A TIFF or a BMP image is saved as PNG, one file per image it holds (`<name>-<n>.png` when several), which the Read tool reads. Each file but an image is converted as `curation-parse` does, its texts beside it; an image is read as it is. Last, only when the article could be converted, the manifest `manifest.json`, the files the curation can use: `article`, with `file`, the original, `text`, its text, and `bytes`, the size of the text; `supplements`, each with the `name` the article gives it, `file`, then `text` and `bytes`, or for a spreadsheet `sheets`, each with `sheet`, its name, `text` and `bytes` (an image: `name` and `file`); `figures`, the paths of the figures. Paths are relative to `<dir>`. A publication directory set up from files the user provides holds the same: each file converted with `curation-parse`, which prints its entry, and the manifest in this format, `bytes` optional.

  It prints its report. First a line saying where the article comes from: `Full text: <PMCID> (<license>)` or `Full text: <source> (<license>, <URL>)`, ending with `, supplementary files missing: <names>` when some are; without the article, `Full text: closed — <why>`, or `Full text: not downloaded — <why>` when it is free but no copy could be downloaded, then every route tried with its outcome. Then one line per file that could not be converted, with why, and per supplementary file missing, with every place tried.

- `uv run curation-download <dir> <url>...`: the file at each URL (a supplementary file the article links to, a commercial construct's page or datasheet): saved in `<dir>` (the type from the response when its name gives none), an archive unpacked (its videos left out), each file but an image converted beside it, as `curation-parse` does; a TIFF or a BMP image saved as PNG. Under a `#` header, one line per file, starting with its URL: its entry, as in the manifest, in JSON, its paths starting with `<dir>` (an image: `file` alone), or why it could not be had (the HTTP outcome, not converted). It ignores an option it does not define, never refuses it.

- `uv run curation-parse <dir> <file>...`: converts each file, a path relative to `<dir>` (the publication directory), to the texts a curation reads, by its type, written beside it and named by their format. Markdown, `<file>.md`: PMC XML (title, abstract, sections, captions, tables and supplementary materials; references, acknowledgements, notes and peer reviews left out), a PMC article page by its structure, as its XML (the same blocks, the back matter left out), any other HTML page (its main text), a Word document (`.docx`, or `.doc` from Word 97-2003). Plain text, `<file>.txt`: a PDF's text page by page (`--- page N ---`), line by line in the order pymupdf reads it, nothing moved; a line read right after another at the same height continues it after a tab, so a table's row the PDF writes cell after cell is one line, while a cell shared by several rows stays on its own lines. TSV, one file per sheet of a spreadsheet (`.xlsx`, `.xlsm`, `.xls`): `<file>.<n>.tsv`, numbered in workbook order, an empty sheet an empty file; its empty rows left out, every other row as many fields as the sheet's widest row. CSV, TSV and plain text are their own text, cleaned in place: in UTF-8 (their encoding found among UTF-8, UTF-16, Windows-1252 and Mac Roman), invisible characters removed, and a CSV's or TSV's rows padded as a sheet's (a TSV split at its tabs; a CSV read as CSV, its separator the one, among comma, semicolon and tab, that gives the most rows the same number of fields); a file whose encoding is not found is refused. Prints each file's entry of the manifest, one JSON line, paths relative to `<dir>`: `file`, then `text` and `bytes`, or `sheets`, each with `sheet`, `text` and `bytes`. A scanned PDF, a damaged file, an image or any other type is refused with the reason, and nothing is written for it. No network.

## NCBI sequences

A strain UniProt lacks is read at NCBI (GenBank, RefSeq), for the mappings taken from its sequence (`curation-rules.md`, the mapping). Read-only, no database; the record used is named in the description note.

- `uv run curation-genbank search <query>... [--limit <n>]`: the GenBank (with EMBL and DDBJ) and RefSeq protein records of each query, never NCBI's copies of Swiss-Prot or PDB, in NCBI search syntax (`JFH-1 AND polyprotein`, `"Hepatitis C virus JFH-1"[Organism]`), or of a nucleotide accession (a genome: the proteins it codes for), bounded and counted as `database-read`: accession and version, title, length, taxon (`<ID> <name>`).
- `uv run curation-genbank seq <accession>[:<start>-<stop>]...`: a protein record: its accession and version, title, length and sequence, or the subsequence between those coordinates (1-based, inclusive). A genome's accession is no protein record: `search` lists its proteins.

`curation-genbank` ignores an option it does not define, never refuses it.

## Notes

- `uv run curation-notes <dir>`: writes `<dir>/publications.jsonl` from the publication notes of a curation batch, each `<dir>/<pmid>/curation.txt`, plain text, as written: one row per note, the PMID its directory's name, the state `selected` when the note starts with `SELECTED`, `curated` otherwise; an empty note gives no row. It never refuses a note.
